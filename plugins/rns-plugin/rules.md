# rns working rules (apply to every code change)

1. **Plan in one table before coding:** each acceptance criterion → the test that proves it. Unclear requirements: pick a sensible default and list it under "Assumptions". Flag any assumption about auth, roles, tenancy, personal data or money as **needs human**.
2. **Red → green:** write the test, see it fail for the right reason, then write the minimum code. A bug fix starts with a regression test that fails on the current code.
3. **Write a test for each of these cases the change touches:**
   - allowed, forbidden and unauthenticated callers, as separate tests
   - two tenants: the other tenant's rows are absent from results, totals and exports, and its ids return not-found
   - every error code returned: force the condition; assert status and code
   - filters: one filter, combined filters, and the total under paging
   - state changes: every rejected transition, and the same request twice
   - output: the response, error or export lacks a field the brief doesn't expose (assert it is absent)
   - input: a body that sets role, tenant, owner, status or price is ignored or rejected
   - personal data: a case/whitespace variant of the identifier is found; after an erase or delete, no stored copy remains (assert the other tables and the audit rows, not just the main field)
4. **Check every hunk you write against 4a and 4b.** Implement a control only if the ticket asks for it or the repo already has the mechanism. Otherwise list it as **needs human**.
   - **4a Security:** endpoints require auth unless the brief says public; enforce roles with the framework's mechanism on the route (policy/attribute), not an inline check · an object loaded by id is checked against the caller on read *and* write · role, tenant and owner come from the verified identity, never the request · bind requests to a DTO, never the entity · responses, errors and events carry only the brief's fields (no hashes, tokens, internal ids) · filter before count and paging · results and exports are bounded · redirect or outbound URLs from the request need an allowlist · "not found" and "not yours" look identical · repeated and concurrent requests are safe · CSV text cells starting with `= + - @` get a `'` prefix; HTML is encoded · no secrets in code or config.
   - **4b Personal data** (name, email, phone, address, national/tax id, birth date, free text, full bodies): first trace each field you touch: every column, table, log, cache, export or derived value that holds it or can re-link to it. Match identifiers normalised (trim; case-fold emails) when you look up, erase or dedupe, so a variant can't escape · after erasure keep neither the value nor a plain hash of it anywhere (audit rows record action, count, actor, time); a subject reference only if the ticket asks for one, as a keyed hash whose secret comes from the repo's existing secret mechanism, else **needs human** · never in logs, exception messages, traces or telemetry: log the record id · fixtures, seeds and snapshots use synthetic values (`@example.com`) · return and store only the fields the use needs · send it only to third parties the brief names · each new personal field gets a Plan `Data` row (classification, retention, erased where); unknown → **needs human** · deletion also reaches copies (cache, search index, exports, soft-deleted rows) · audit exports and deletes if the repo has an audit mechanism, else **needs human** · a new processor, cross-border transfer or special-category field (health, biometric, religion…) → **needs human**.
5. **Fit the repo:** reuse existing helpers (error shape, paging, tenant filter). No new abstractions, no drive-by refactors. Never edit CI, infra, lockfiles or secrets. Read `AGENTS.md` first and reuse the mechanisms it lists. Org numbers and rules: `{{PLUGIN}}/org/policy.md` (the repo's AGENTS.md guardrails win).
6. **Before finishing:** run the full build and tests, then `node "{{PLUGIN}}/scripts/gate.mjs" <base-commit>`. Re-read your diff against rules 3, 4a and 4b and add any missing test. If AGENTS.md exists and the change added a feature, mechanism, invariant or personal field, update its rns block in the same commit. Resolve every gate WARN (fix it, or one line on why it's fine). No Node → record `Gate: NOT RUN (node missing)`. End with a short report: what changed, tests added, and the **needs human** items.
